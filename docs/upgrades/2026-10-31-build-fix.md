# 26.1027 构建失败修复

## 失败证据

[GitHub Actions 运行 41209341828](https://github.com/siyuan-123/CodexDesktop-Rebuild/actions/runs/41209341828) 的 Windows、macOS x64/ARM64、Linux x64/ARM64 五个任务均在 Patch 阶段失败，构建和发布尚未执行。上游 macOS 为 `26.1027.30824`（build `22943`），Windows MSIX 为 `26.1027.3384.0`，包内应用版本同为 `26.1027.30824`。

现有 133 项回归测试通过，但旧测试没有覆盖最新主进程 chunk 结构。四个显式失败的补丁是 copyright、devtools、codex-home-env、diff-limits；此外 worker-limits、CDP、Sentry、插件默认功能和更新器存在未命中却返回成功的路径。

## 原因与修复

| 模块 | 上游变化 / 问题 | 修复 |
| --- | --- | --- |
| bundle 定位 | `main-*.js` 拆到 `early-bootstrap-<编号>-<hash>.js`，Git 执行器也进入共享 chunk | 按代码内容查找全部目标，每个请求平台单独检查，缺失目标直接失败 |
| About 版权 | HTML 中 `©` 变为源码转义 `\xa9` | 兼容转义和字面量，校验生成 HTML 与重复应用 |
| DevTools | 窗口配置迁移到新 chunk | 保留 AST 属性规则，覆盖实际窗口配置，跳过解构参数 |
| CODEX_HOME | native-pipe 启动器由具名函数变为匿名函数 | 根据解构参数和函数体定位，在启动前设置环境变量，保留已有值 |
| diff 输出上限 | 三个连续常量被内联为 `null==m?0x2000000:Math.min(m,0x2000000)` | AST 关联输入和输出，将默认值和硬上限改为 8MB，保留更小限额及其他 32MB 常量 |
| worker 内存 | Git worker 改为 Electron utility process，其余仍使用 worker thread | 线程保留 1024MB/128MB 上限；独立 Git worker 经 `--js-flags` 设置 1024MB 老生代上限 |
| CDP 截图 | 转发返回值增加结果包装函数 | 只包裹 CDP 转发的 params，保留 method、session、超时和响应处理；视口截图和非截图命令不变 |
| 插件 | 嵌套模块函数使同一 AST 替换位置被访问两次 | 替换去重、重叠检查与写入前语法校验，恢复新 chunk 中的功能补丁 |
| 更新器 | 平台策略从对象方法变为箭头函数，并增加 Linux 更新策略 | 兼容两类函数，禁用各平台自动更新以保留重建补丁 |
| Sentry | breadcrumb 截断与 scope 文件保护分布在不同 chunk | 在同一平台的相关 chunk 中联合确认原生保护；不覆盖上游已有处理 |

## 验证

- 行为测试覆盖旧版与新版结构、已有配置保留、diff 默认值/更小值/超大值、CDP 参数和响应、插件重复替换、更新器副作用、目标缺失、`--check` 只读性与重复应用幂等性。
- Electron utility process 实测：直接使用 `--max-old-space-size=1024` 时堆上限仍为 4GiB；使用 `--js-flags=--max-old-space-size=1024` 后为 1120MiB（包含老生代以外的 V8 空间）。参数入口见 [Electron utilityProcess 文档](https://www.electronjs.org/docs/latest/api/utility-process)。
- 真实资源使用上述版本的 Windows 完整安装包和 macOS 两种架构的 ASAR、外置 Browser 服务副本。macOS/Linux 安装包在各自 GitHub runner 上完成构建验证。
